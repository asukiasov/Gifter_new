# Database Development Workflow

This guide ensures consistency between the SQL Server schema (SmarterASP) and the C# application code.

## 1. Schema Consistency
The database uses a strictly typed naming convention: `TableName + Property` (e.g., `GiftTitle`).

### Column Naming Rules:
- **Primary Keys**: `TableNameID` (e.g., `GiftID`).
- **Foreign Keys**: `TableName` + `ReferenceTableID` (e.g., `GiftGiftListID`).
- **Logic Flags**: `TableName` + `IsDescription` (e.g., `GiftListIsSecret`).

## 2. Managing Changes
When adding a new feature (e.g., adding a "Currency" column):

1. **SQL Script**: 
   - Add the column to the table.
   - **Critical**: Update the `GiftsIUD` stored procedure to include the new parameter.
   - **Critical**: Update the `GiftsGet` function/view to return the new column.
2. **C# DTOs**: 
   - Update `GiftsDTO` (for retrieval).
   - Update `GiftsIudDTO` (for inserts/updates).
3. **Repository**: Use the `ToSqlParameter` extension to map the DTO property to the SQL parameter.

## 3. Stored Procedure Pattern (IUD)
All data modifications must go through an `IUD` (Insert, Update, Delete) procedure.

Every IUD procedure follows this exact signature:

```sql
CREATE PROCEDURE [dbo].[TableNameIUD]
(
    @Action       TINYINT,          -- 0 = INSERT, 1 = UPDATE, 2 = DELETE
    @TableNameID  INT OUTPUT,       -- receives SCOPE_IDENTITY() on INSERT
    @TableNameJson NVARCHAR(MAX)    -- single JSON blob carrying all DTO fields
)
```

Key details:
- **Action is a TINYINT**, not a varchar. The C# enum `Enums.DatabaseActions` maps: `INSERT = 0`, `UPDATE = 1`, `DELETE = 2`.
- **Data arrives as one JSON string**, not as individual parameters. Extract fields inside the procedure using `JSON_VALUE(@Json, '$.PropertyName')`.
- **Booleans in JSON are `true`/`false` strings** when extracted by `JSON_VALUE`. You cannot `CAST` them to BIT directly — use a CASE: `CASE WHEN JSON_VALUE(@Json, '$.Flag') = 'true' THEN 1 ELSE 0 END`.
- **NULL = "don't change"** on UPDATE. Use `COALESCE(new_value, current_column)` for scalar fields. For booleans, check `IS NOT NULL` first.
- **Atomic Ops**: The procedure handles all logic (timestamps, cascading deletes) internally.

## 4. Troubleshooting SmarterASP SQL
- **Timeout Errors**: Occur if a procedure is locked. Ensure all connections in the Repository use the `using (var dbContext = ...)` pattern to guarantee disposal.
- **Invalid Column Name**: Usually means the code was deployed but the SQL script (altering the table or view) was not run on the server. Always run SQL scripts **before** deploying binaries.

## 5. SmarterASP Constraints

The SmarterASP SQL editor **does not support `GO`** as a batch separator. Each DDL statement (CREATE TABLE, CREATE PROCEDURE, CREATE FUNCTION) must be executed as a separate run in the editor. You cannot paste a multi-statement script that relies on `GO` between blocks.

Exceptions — the following multi-statement patterns work in a single run because they are a single logical batch:
- `SET IDENTITY_INSERT … ON` → `INSERT …` → `SET IDENTITY_INSERT … OFF`
- A stored procedure body (everything between `BEGIN … END` is one statement)

Always run SQL scripts **before** deploying application binaries.

## 6. Function Conventions

Two function types are used for data retrieval. The type determines how `SqlQueryBuilder` calls it and what the SQL must return.

### Scalar-Valued Functions (single-record retrieval)

Called as `SELECT dbo.FnName(…)`. Must return `NVARCHAR(MAX)` containing a JSON object. The repository deserializes this JSON into a DTO.

```sql
CREATE FUNCTION [dbo].[UsersGetSingleByID](@UserID INT)
RETURNS NVARCHAR(MAX)
AS
BEGIN
    RETURN (
        SELECT col1, col2, …
        FROM …
        WHERE …
        FOR JSON PATH, WITHOUT_ARRAY_WRAPPER
    )
END;
```

- Use `JSON_QUERY(COALESCE((subquery FOR JSON PATH), '[]'))` to embed nested arrays (e.g. a user's permissions list) without double-escaping.
- If no row matches the WHERE clause, the function returns NULL. The repository handles this gracefully.

### Table-Valued Functions (list retrieval)

Called as `SELECT col1, col2 … FROM dbo.FnName(…)`. The column list in the SELECT is **auto-generated by reflection** on the C# DTO type — `SqlQueryBuilder` reads every property name from the DTO class and builds the SELECT from it.

This means: **column names in the TVF must match C# DTO property names exactly, case-sensitive, PascalCase.**

```sql
CREATE FUNCTION [dbo].[UsersList]()
RETURNS TABLE
AS
RETURN
    SELECT UserID, RoleID, UserEmail, …   -- names must match UsersListDTO properties
    FROM [dbo].[Users];
```

Use inline TVFs (single `RETURN` statement) wherever possible. Recursive CTEs are allowed inside inline TVFs on SQL Server 2016+.
